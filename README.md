# 定时考勤助手

针对 vivo S9 / Android 13 的本地 Android 工程。每天北京时间 09:00 上班、22:00 下班，通过无障碍操作飞书；失败持续闹钟，明确关闭后停止。

## 当前验证边界

代码包含完整调度、任务状态、本地存储、页面解析、单次提交保护、持续响铃、配置和测试入口。默认暂停自动任务，飞书适配默认未核对。示例入口“工作台 → 考勤”是待核对配置，不代表已在用户手机上验证。

模拟页面测试不能替代 vivo 后台运行、真实飞书无障碍节点和真实打卡验收。构建和测试结果见 [验证记录](VALIDATION.md)。

## 安装与首次设置

1. 安装交付的调试 APK；手机保持无需密码解锁，飞书已登录。
2. 打开助手，允许通知、闹钟和提醒，在无障碍设置中启用“定时考勤助手”。侧载若被系统限制，先在应用详情中允许受限设置，再启用无障碍。
3. 在 vivo 设置中允许自启动与后台运行；电池优化设为不受限制。保持闹钟音量可听，测试勿扰和蓝牙输出。
4. 确认飞书包名与入口文字。国内版候选包名为 `com.ss.android.lark`；实际包名和页面需在设备上确认。每行一个导航入口，保存会暂停任务并清除旧的适配确认。
5. 点击“仅导航测试 · 不提交打卡”，观察能否进入当天考勤，返回助手检查识别结果。测试不会触发打卡提交。
6. 只有识别的日期、上下班分组、记录、范围与飞书实际一致时，才点击“核对并确认当前版本适配”。版本或入口改变后需重做测试。
7. 执行持续闹钟测试，验证熄屏、后台、打开飞书后仍持续提醒，且“关闭全部闹钟”有效。
8. 完成以上检查后启用每日任务。先在可观察的真实打卡窗口验收，再进行长时间熄屏测试。

## 执行行为

- 在计划时间开始打开飞书；实际记录时间受网络、页面加载影响。
- 必须识别当天日期、对应班次、范围和唯一按钮。信息缺失或有歧义时停止并响铃，不使用固定坐标盲点。
- 对应记录已存在则跳过；晚上不会点击新出现的上班按钮。
- 范围外等待 30 秒后再读取一次，仍不满足则响铃。
- 提交前持久化提交阶段，最多点击一次；点击失败、进程中断或结果不明均不自动重试。
- 执行总时限 120 秒。每日执行由精确闹钟触发，另有系统可见的失败兜底闹钟，因此系统状态栏可能显示下一次提醒时间。
- 首次启用只安排未来任务。恢复时，已有的未完成任务距目标不超过 5 分钟可补执行，超过只提醒；已经失败并提醒的任务不会自动重新提交。
- 暂停会停止自动操作并取消未来任务；已响起的失败闹钟仍需明确关闭。
- 打开飞书不会停止响铃，关闭闹钟不会记为打卡成功。

关机、强行停止、系统完全禁用应用时，APP 无法保证执行或提醒。勿扰、零音量和蓝牙输出可能影响声音，必须自行完成声音验收。

## 开发与构建

JDK 17、Android SDK 36 / Build Tools 35.0.0、AGP 8.10.1、Gradle 8.11.1、Kotlin 2.1.20；首版 `minSdk=33`、`targetSdk=33`，仅为 Android 13 单机本地安装设计。Android 14 及以上模拟器只用于逻辑与界面验证，不承诺系统兼容。

在工程根目录配置 `ANDROID_HOME`，然后运行：

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。Gradle Wrapper 固定官方分发地址和 SHA-256。若网络无法访问官方重定向域名，可使用经官方 SHA-256 校验后的本地 Gradle 8.11.1 运行同样任务；不要关闭 TLS 验证。

### 设备集成测试

仅在模拟器或专用测试设备上运行，避免修改日常使用手机的无障碍设置。测试使用 debug 专属模拟考勤页面，不接触真实飞书账号。安装应用后在模拟器授予通知、精确闹钟并启用无障碍，再运行：

```sh
./gradlew :app:connectedDebugAndroidTest
```

测试覆盖数据库并发提交预留、仅导航提交禁令、成功与超时冲突、明确关闭状态、暂停恢复、真实无障碍节点读取与模拟按钮操作，以及失败服务后台持续运行。模拟页面仅在 debug 源集中，release 不包含。

无线上传、不收集登录或解锁凭据、不申请定位或联网权限。Room 保存任务与简短阶段日志，终态数据保留 30 天；未关闭的失败提醒不会按时间自动清除。
